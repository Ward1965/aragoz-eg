# Standning instructions (GLOBAL RULE — follow in EVERY session)

## Always before every push to GitHub
1. Bump the version number in `frontend/index.html` (BOTH places):
   - line ~130: `<span class="footer-version">vX.Y</span>`
   - line ~244: `<span class="welcome-version">vX.Y</span>` (the splash/welcome overlay)
   Ask the user for the new version number if they did not specify it.
2. Rebuild the program for all required systems (Windows / macOS arm64 / Linux x64):
   - Local Windows build: PyInstaller onefile (`Aragoz Lite.spec`) then sign.
   - The other systems build automatically via the CI workflow when the tag is pushed
     (.github/workflows/build.yml builds on `v*` tags and creates a GitHub Release).
3. Commit + tag (`vX.Y`) + push to origin (https://github.com/Ward1965/aragoz.git, branch main).

## Local Windows build pattern (only working one — PowerShell)
- First kill: `Get-Process -Name "Aragoz Lite"` and `python` → Stop-Process -Force
- Prepend UPX to PATH: `$env:PATH = "C:\Users\HP Book\AppData\Local\Temp\opencode\upx-5.0.2-win64\upx-5.0.2-win64;" + $env:PATH`
- `& "C:\Program Files\Python313\python.exe" -m PyInstaller --noconfirm --clean "I:\Aragoz Lite 1.3\Aragoz Lite.spec"`
- Success = "Build complete!" and fresh LastWriteTime on `dist\Aragoz Lite.exe`.
- If exit=-1 and log stops during "Processing standard module hook 'hook-PyQt5..." retry — it can be transient.
- Sign: cert thumbprint `0E99DFE9C959ADD2A64B8EBB3CE3CD95E0F2E1FA`, SHA256,
  timestamp `http://timestamp.digicert.com`; verify `Get-AuthenticodeSignature` = Valid.
- Cold test: poll `dist\logs\aragoz.log` for "Application windows created".

## Do NOT commit
- Dev harness scripts: `_*.py` at repo root (they are gitignored).
- Build artifacts: `dist/`, `build/`, `.splash_baked.png`.
- `splash_b64.py` gets regenerated by each build (baked splash image) — include its change in the commit.
